## 2026-08-31 · MVP v0.7 实施进度

### 真实双边案例与定向澄清

- 默认真实市场只比较数据库中的真实租客与真实房源；演示语料与真实双边案例完全分离。
- 每一对真实任务只有一个权威案例，双方候选投影在同一事务写入；输入版本变化会重算并产生新条款版本。
- 无硬冲突但信息不足时，规则每轮最多选择三个高价值问题，按资格安全、硬条件、价格租期费用和沟通成本排序。
- 问题只发给能够回答的一方；本人可见具体问题，对方仅可见待补充数量和粗粒度类别。
- 回答由固定 schema 校验，并原子写入 `counterparty_answer` 字段版本、任务输入版本、案例事件和 outbox；随后自动重算为继续澄清、条款就绪或冲突失效。
- Qwen 只能润色规则已经选定的问题，不能修改字段、答案类型或枚举选项；不可用或输出越界时回退到规则模板。
- 使用 `Qwen/Qwen3.5-35B-A3B` 完成单次真实契约冒烟：严格字段校验通过，消耗 254 tokens，API Key 未进入仓库或报告。
- 有效匿名会话在页面刷新时复用原账号，不再因为重复调用会话入口而丢失任务与候选。

### 界面

- 租客房源详情与出租方租客详情都接入真实案例进度。
- 单选、数值、日期、日期范围和短文本分别使用对应控件；提交期间明确显示“正在写入新版本并重新匹配”。
- 未完成阻断澄清时，页面不会允许继续执行双方确认。
- Playwright 已验收 390×844 与 320×568：无横向溢出；案例回答前后状态正确；控制台在服务器稳定运行期间为 0 错误、0 警告。

### 同版条款确认

- 公开条款只接受月租、租期、入住日期、费用规则、大致位置、看房安排和房源要点；对象键排序、数组去重排序后生成 `sha256:` 哈希。
- 租客与出租方的确认都绑定同一条款版本、同一哈希和双方任务输入版本；任一输入变化会保留旧记录并写入撤销时间。
- 服务端恢复 `pending/confirmed/declined` 状态；重复确认幂等，过期版本或哈希返回 409，第三方读写返回 404。
- 详情页按真实状态展示“待你确认”“你已确认，等待对方”“对方已确认，等待你”“双方已确认”“条款已变化，需要重新确认”和“匹配已失效”。
- 固定演示联系人和客户端解锁状态已经移除；联系方式是否可读完全由服务端授权事实决定。

### 联系人门禁与授权撤销

- real 模式启动时强制校验 `CONTACT_ENCRYPTION_KEY`；联系人使用随机 12 字节 nonce 的 AES-256-GCM 信封落库，同一明文重复保存得到不同密文。
- 手机、微信和邮箱先经过类型、长度和格式规范化；普通资料接口只返回掩码，原值不会进入候选、案例、事件、异常、分享文本或浏览器本地存储。
- 当前用户未设置联系人时不能确认。第二方确认与案例进入 `mutually_confirmed`、授权快照和 `contact.granted` 事件在同一事务中完成，任一步失败全部回滚。
- 授权绑定案例、条款版本、条款哈希、双方任务输入版本、双方 owner 和有效期；读取时再次核对全部事实，不只检查 `revoked_at`。
- 租客只能读取出租方联系人，出租方只能读取租客联系人；第三方和跨案例读取返回 404，单方确认、旧条款或失效授权返回 403 `CONTACT_LOCKED`。
- 条款或输入变化、任务暂停/关闭/过期、案例失效、任一方拒绝和授权过期都会重新锁定；撤销与查看事件只记录 ID、版本和原因码。
- 前端在“设置”中加密保存联系人，双方确认后仍需主动点击查看；原值只在当前详情页内存中临时存在，离开页面即清除。

### 公开房源图片隐私管线

- 引入并锁定 `sharp`；公开图片不再相信文件扩展名或客户端 MIME，而是先真实解码并核对 JPEG、PNG、WebP 格式。
- 路由与服务分别限制 JSON 字节、原始图片字节、像素总量、动画页数和最长边；文本伪图片、MIME 伪装、动画 WebP 与像素炸弹会被拒绝。
- 原图写入 `private-originals/`，公开图自动旋转、缩放并重新编码为 WebP 后写入 `public-derivatives/`；默认剥离 EXIF、GPS、XMP 和 IPTC。
- 发布者需要单独勾选公开授权；候选负载只携带媒体 ID、受控 URL、说明和尺寸，不携带原图、私密 evidence ID 或磁盘路径。
- 图片读取要求当前会话是发布者或真实候选接收方；无会话、第三方、私密 evidence ID、失效任务和已删除媒体均不可读。
- 同任务同内容哈希重复上传复用既有媒体，不重复写文件；任务删除后媒体立即失效并进入独立清理队列。
- 候选卡、详情和分享预览改用 `<picture>/<img>`；用户房源无公开图片时显示中性占位，service worker 不缓存任何 `/api/` 响应。

### Transactional Outbox 持续匹配

- 任务创建、字段答案、暂停、恢复、关闭和到期都与匹配事件在同一 SQLite 事务提交；`clientRequestId` 重放返回原任务，不重复创建任务或事件。
- 新增 outbox 仓储和单进程 worker：短事务领取、worker ID 租约、指数退避、超时锁回收、最大尝试次数和终态告警均有确定状态。
- 配对 job key 绑定双方任务 ID、双方输入版本和 evaluator 版本；重复事件跳过已完成作业，处理期间版本变化的旧结果会被丢弃。
- 真实市场先按相反任务类型、有效期、城市、粗位置、可计算通勤和授权价格做保守粗筛；未知字段不会被提前排除，最终结论仍由确定性 pair evaluator 给出。
- 定时器已降为补偿器，只处理到期任务、超时 outbox 租约、异常遗漏事件、过期联系人授权、会话和媒体清理，不再周期性全量跑全部活跃任务。
- `/api/health` 分别报告数据库、AI、worker 最近成功/失败、pending/processing/failed 数和 job P50/P95；存在终态失败事件时返回 degraded。
- 200 租客 × 50 房源性能用例中，修改一个租客只评估 10 个粗筛相关房源，没有重跑 10,000 对。

## 2026-08-23 · MVP v0.1

### 已验证的产品判断

- 入口应是“创建委托”，而不是“浏览帖子”。
- AI 补问必须把硬条件与加分偏好分开，否则用户不知道为什么少了候选。
- 候选卡必须同时展示匹配理由、明显缺点和事实来源。
- 双方 AI 对话应表现为可审计事件，不展示隐藏思维或对方私密底价。
- 强处罚与防恶意举报可以兼容：举报后立即隔离，客观证据确认后再执行实名级永久封禁。

### 本轮自动发现并修复

1. **过期房源状态枚举不一致**
   - 底层使用 `exclude`，汇总层只识别 `excluded`。
   - 影响：已排除数量少算，测试台误判。
   - 修复：统一为 `excluded`，加入自动回归。

2. **新页面继承旧页面滚动位置**
   - 从较长的委托确认页提交后，结果页可能直接落在候选卡中部。
   - 影响：用户错过 AI 扫描和风控摘要。
   - 修复：以导航视图键区分页面；跨页面切换归零，同页交互保留滚动。

3. **补问答案只改文案、不改规则的风险**
   - 初版模拟数据固定使用默认委托。
   - 影响：“必须独卫”“不接受合租”等选择可能成为假交互。
   - 修复：提交时从界面答案构造真实委托，硬条件进入引擎判定。

4. **浏览器缺少 favicon 产生 404**
   - 影响：控制台不干净，可能掩盖真实资源错误。
   - 修复：复用本地应用图标，并重新验证控制台为 0 错误、0 警告。

5. **桌面预览可能产生外层页面滚动**
   - 影响：设备框顶部在自动点击后可能被浏览器滚出视口。
   - 修复：锁定外层页面滚动，仅允许应用主内容区滚动。

### 下一轮优先验证

1. 用户是否理解“私密授权”和“非约束性意向”的区别。
2. 三套候选是否足够，还是需要“再找一轮”而不是增加一次交付数量。

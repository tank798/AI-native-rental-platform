# MVP 测试矩阵

## A. 找房委托

1. 初始输入为空，不展示示例按钮或预填文案。
2. 空输入不能进入补问。
3. 自由输入会解析区域、预算、入住、通勤、合租和设施条件。
4. 原话无论完整与否都进入一次对话式确认；已识别字段预填，缺失字段明确等待补充。
5. 浏览器支持 Web Speech API 时可语音输入，不支持时回到键盘。
6. 室友性别选择会真正改变硬性匹配条件。
7. 选择“不接受合租”后，存在室友的房源全部排除。
8. 选择“必须独卫”后，共用卫生间房源全部排除。
9. 选择“必须有电梯”后，无电梯房源全部排除。
10. 未确认委托时不能开始寻找。
11. 页面切换后回到顶部，同页选择和勾选保留滚动位置。

## B. 匹配与议价

12. 只允许 `landlord` 与 `subletter` 角色进入匹配。
13. 申报角色与证据冲突时立即隔离。
14. 中介费或服务费大于零时立即隔离。
15. 盗图证据命中时立即隔离。
16. 过期现场核验不能继续匹配。
17. 室友性别、通勤、入住日、厨房和洗衣机硬冲突会排除。
18. 挂牌 3,200 元可按“12 个月 + 提前起租”协商到 3,000 元。
19. 对方底价高于私密上限时停止议价。
20. 用户审计记录不得出现 `hardMax` 或“最高预算”措辞。
21. 未知水电、物业、网络、洗衣机信息必须显式标为尚未确认。
22. 候选最多三套，覆盖综合、低价、居住条件三种选择理由。

## C. 候选交付

23. 卡片至少展示一个缺点或未知项。
24. 出租方文案不会原样展示，事实按租户委托重新组织。
25. 身份、出租权、当前租金、现场信息分别标注来源。
26. 协商记录只展示结构化事件、真实报价与条件，不展示隐藏推理。
27. 结果始终标注为非约束性意向。
28. 双方本人确认前，不开放直接联系。

## D. 出租发布

29. 只有房东本人和当前承租人两个角色选项。
30. 完整地址只用于平台核验，不直接公开。
31. 必须完成身份、角色、出租权、现场四项核验。
32. 中介费、服务费、信息费、带看费或签约费任一不为零都不能发布。
33. 未签署零中介承诺时不能发布。
34. 发布后只接收满足硬条件的结构化委托，不开放公开留言。

## E. 举报与处罚

35. 提交举报后，房源立即退出新匹配。
36. 无客观证据的单次举报进入隔离复核，不直接执行不可逆封禁。
37. 站内收费对话或角色材料冲突命中后，执行下架、冻结与实名级永久封禁。
38. 处罚结果明确显示立即动作、最终动作和申诉通道。

## F. 体验质量

39. 主要按钮和选项触控区域不小于 44×44 px。
40. 键盘焦点可见，主要控件有可访问名称。
41. 减少动态效果设置与系统 `prefers-reduced-motion` 均生效。
42. 320×568、390×844 和桌面设备框三种尺寸可滚动、无横向溢出。
43. 页面控制台没有 404、JavaScript 错误或警告。

## G. 连续输入

44. 地点输入支持任意商圈、地铁站或地址，不依赖四个固定选项。
45. 预算分别填写理想价格和最高价格，单一模糊预算不会自动猜测上限。
46. 入住时间使用最早、最晚两个日期输入，最早日期不得早于当天。
47. “时间灵活”不会自动换算为固定天数，仍需填写日期范围。
48. 通勤滑杆覆盖 15–60 分钟并实时显示当前值。
49. 首页 Enter 提交，Shift+Enter 换行，中文输入法组词期间不误提交。
50. 出租方可直接修改可入住日期，确认页不使用写死日期。

## H. 当前任务架构

51. 底部只有“首页、候选、消息、我的”四个导航项；加号是独立新建动作。
52. 点击加号后明确选择找房任务或出租任务，不存在覆盖全局的大型模式切换。
53. 找房位置从地图选择界面进入，支持多区域、搜索、自定义地点、半径和系统定位入口。
54. 出租照片入口同时提供系统相机和系统相册选择，并能预览实际选中的媒体。
55. 发布找房后先进入持续匹配状态，不会在同一帧直接展示最终候选。
56. 发布出租后运行对称租客匹配，不使用写死的租客数量和报价。
57. 首页不显示阶段卡、任务胶囊、环形节点或事件流，只展示持续状态、已查看和合适两个真实数字。
58. 首批候选交付后任务仍保持活跃，直到用户暂停、关闭或确认成交。
59. 候选页、详情页和协商记录不出现“已核验”标签。
60. 出租端最低租期冲突会被排除。
61. 信息费、带看费与签约费和中介费、服务费一样阻止发布或匹配。
62. 统计面板的生产数据必须由业务事件聚合，不由客户端凭空累加。
63. 390×844 与 320×568 的首页、地图、表单、动态匹配与候选页均无横向溢出。

## I. 对话式双边委托

64. 找房原话可抽取租期、楼层、朝向、看房时间、网络与洗衣机类型，并可在确认卡中修改。
65. 出租原话可抽取本人角色、地址、挂牌价、最低授权价、入住日、楼层、面积、室友、设施与费用。
66. 中介、公寓管家、中介代发或任一种服务收费在进入匹配前被规则拦截。
67. 找房与出租确认后分别扫描 100 套房源或 100 位租客，结果可以匹配，也可以诚实为空。
68. 候选详情展示双方分身的结构化请求、回应、议价与非约束性意向，不展示隐藏推理或私密底线。
69. 100 条出租文案与 100 条找房文案的关键字段解析结果均与案例真值一致。

## J. 真实双边案例与定向澄清

70. 两个不同账号的真实任务只产生一个双边案例，重复调度不会重复创建案例或条款版本。
71. 演示候选不产生双边案例，也不会进入确认与联系方式授权链路。
72. 存在阻断未知项时不得假装匹配完成；每轮最多向正确一方提出三个问题。
73. 已回答、仍然打开或已由用户确认的字段不会被重复追问。
74. 非目标方读取回答接口返回 404；同答案重放返回 200，不同答案重放返回 409。
75. 数值、枚举、日期和短文本答案必须先通过固定 schema 与范围校验。
76. 回答后字段版本和任务输入版本递增，并在同一事务写案例事件与 outbox。
77. 回答触发自动重算，案例只会继续澄清、进入条款就绪或因硬冲突失效。
78. 案例响应不包含另一方最高预算、出租底价、原始输入、会话信息或材料路径。

## K. 同版条款确认

79. 同语义不同键顺序的公开条款得到相同 `sha256:` 哈希，任一公开字段变化得到不同哈希。
80. 公开条款出现 allowlist 外字段或私密字段时显式失败，不能静默删除后继续。
81. 第一方确认后案例保持等待，第二方确认同一版本和哈希后才进入 `mutually_confirmed`。
82. 过期版本或哈希返回 409；相同确认重放不重复写事件。
83. 任一方拒绝后，另一方不能继续确认该版本。
84. 条款变化或任一任务输入版本变化都会撤销旧确认，并保留撤销历史。
85. 重复持续调度不会把 `awaiting_confirmations` 或 `mutually_confirmed` 降回 `terms_ready`。
86. 刷新页面后确认状态完全由服务端恢复，客户端不存在固定联系人或本地解锁真值。

## L. 联系人授权门禁

87. real 模式缺少有效的 32 字节 base64 联系人密钥时拒绝启动；demo 模式不会生成真实联系人授权。
88. 手机、微信和邮箱经过固定格式与长度校验，资料接口只返回掩码。
89. 同一联系人重复保存使用不同随机 nonce；错误密钥或篡改 auth tag 必须稳定失败。
90. 本人未设置联系人时确认返回 422 `CONTACT_REQUIRED`，且不留下半条确认记录。
91. 单方确认后双方读取联系人都返回 403 `CONTACT_LOCKED`。
92. 双方同版确认后只创建一个绑定条款哈希和双方输入版本的有效 grant。
93. 租客只能读取出租方联系人，出租方只能读取租客联系人；第三方和跨案例访问返回 404。
94. 重复读取不重复创建 grant；`contact.viewed`、`contact.granted` 和 `contact.revoked` 事件不包含联系人原值。
95. 条款或输入版本变化、任务暂停/关闭/过期、案例失效、拒绝和授权过期都会立即重新锁定。
96. 联系人原值不进入候选、案例 JSON、分享文本、history state 或 localStorage，离开详情页后从内存清除。

## M. 公开房源图片

97. 文本、SVG 脚本或其他不可解码内容即使声明为 JPEG 也会被拒绝。
98. 文件真实格式必须与声明 MIME 一致；只接受 JPEG、PNG 和 WebP。
99. 超过路由字节、原图字节、像素总量或动画页数限制的输入在写文件前失败。
100. JPEG 中的 EXIF/GPS 在 WebP derivative 中不存在；自动旋转后的宽高和最长边受限。
101. 用户文件名不会参与服务端路径；原图与 derivative 只使用随机媒体 ID。
102. 同任务同内容哈希重复上传返回同一媒体 ID，私密原图和 derivative 均不重复占空间。
103. 只有 `public_listing`、明确公开同意、净化通过、任务有效且未删除的媒体能进入候选。
104. 发布者和真实候选接收方可读取公开 derivative；无会话、第三方和私密 evidence ID 返回 401/404。
105. 删除任务后公开媒体立即不可访问，并写入独立清理队列等待物理文件回收。
106. 候选卡、详情和分享预览使用真实 `<picture>/<img>`；无公开图时显示中性占位，不显示演示样板房。
107. service worker 只缓存 allowlist 且 `response.ok` 的静态资源，从不缓存任意 `/api/` 响应。

## N. Transactional Outbox 持续匹配

108. 创建任务与 `task.match_requested` 必须在同一事务；outbox insert 失败时任务和审计事件一并回滚。
109. 相同 owner 与 `clientRequestId` 重放返回原任务，且同一 `taskId + inputVersion` 只有一个标准匹配事件。
110. 字段版本、暂停、恢复、关闭和到期变化会提升任务输入版本，并原子写入重算或失效事件。
111. 两个 worker 竞争时，同一事件只能被一个 worker ID 持有；非持有者不能完成或改写该事件。
112. 可恢复失败增加 attempts 并按 fake clock 指数退避；超时 `processing` 租约可回收，达到上限进入 `failed` 并写告警事件。
113. pair job key 固定绑定双方任务 ID、双方输入版本和 evaluator 版本；同一版本重复事件不重复评估或创建案例。
114. worker 写候选前重新读取双方版本；旧事件与处理中变化的旧结果都只能记为 stale，不能覆盖新版本。
115. 粗筛只排除确定不可能的城市、位置和价格组合；未知项保留给最终 pair evaluator 判断。
116. 200 租客 × 50 房源中修改一个租客只评估 10 个受影响房源，不重新运行 10,000 个任务对。
117. 调度器只补发长期未匹配且没有 pending/processing event 的异常任务，并按时间桶去重补偿事件。
118. 健康检查分别报告 SQLite、AI、worker 最近成功/失败、队列状态和作业 P50/P95；终态失败时不能返回 healthy。

## O. 生命周期、通知与可操作结果

119. 新任务默认有效 14 天，到期前 48 小时只生成一次持久续期提醒。
120. 续期从当前到期日或当前时间中较晚者再延长 14 天，并提升输入与生命周期版本。
121. 过期任务保持只读，可以克隆为新任务，不能静默恢复旧授权。
122. 通知未读数由服务端维护，单条已读与全部已读在刷新后保持。
123. 只有联系人授权有效时才能提出看房；只能由另一方接受或拒绝。
124. 任务暂停、关闭、过期或案例失效会取消未完成看房提议。
125. 举报写入服务端持久表，原因码受 allowlist 约束，第三方不能替案例参与方提交。
126. 产品事件按固定 schema 和 dedupe key 写入，任何层级私密字段都会在写入边界被拒绝。
127. 指标摘要只输出聚合漏斗与耗时，不输出任务 payload、联系人、地址、原话、预算上限或底价。

## P. 最终双边发布闸门

128. API smoke 从 real 模式空市场开始，首个租客任务的 seed 候选数必须为 0。
129. 四类材料经过服务端审核、公开图经过真实解码后，双方得到同一个 `matchCaseId`。
130. 阻断未知项由目标方回答后，双方看到相同条款 version/hash。
131. 租客单方确认后联系人仍锁定，出租方同版确认后双方只读取对手联系人。
132. 第三方读取案例与联系人均返回 404。
133. 房源暂停后旧 grant 立即失效；恢复并重算后显示需要重新确认。
134. 双边 smoke 扫描全部公共 JSON，`privateLeakCount` 和 `seedCandidateCount` 都为 0。
135. 双浏览器账号覆盖自然语言 intake、用户修正、材料、公开图、两轮澄清、同版确认、联系人解锁、刷新恢复和变更撤销。
136. 320、375、430 px 均无水平溢出；Enter、Tab、Shift+Tab 与 Esc 覆盖关键键盘路径。
137. Qwen 超时/429/坏 JSON、worker 租约回收、SQLite 锁、幂等重试、恶意图片、会话撤销、确认冲突和暂停前读取均有明确故障策略。

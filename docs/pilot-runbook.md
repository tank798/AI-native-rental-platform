# 住哪儿受控试点运行手册

本文用于本地或内部测试环境的受控 alpha。它不是公开生产环境操作手册，也不授权收集真实证件、租约、联系方式或交易资金。

## 1. 试点目标与边界

本次试点只验证一件事：租客和出租方能否分别通过 AI 对话完善信息，由系统持续匹配、定向补问、生成同版条款，并在不进行前置真人聊天的情况下到达双方确认、联系人解锁和看房安排。

“真实双边”表示双方任务、案例、条款、确认、授权和失效状态都由服务端持久化并实际执行，不表示身份、产权、租约或房源真实性已经接入官方核验。演示 fixture 永不生成可确认案例，也不会签发联系人授权。

首轮仅允许内部测试人员使用虚构数据。禁止上传真实身份证、房产证、租约、手机号、微信号、邮箱、Cookie、API Key 或未脱敏地址。

## 2. 启动前检查

### 2.1 环境

- Node.js 22 或更高版本，推荐 Node.js 24。
- 从 `.env.example` 创建 `.env.local`，只填变量，不把值提交到 Git。
- `CONTACT_ENCRYPTION_KEY` 必须是本机新生成的 32 字节 base64 值。
- Qwen 可选；只引用 `SILICONFLOW_API_KEY` 或 `SILICONFLOW_API_KEY_FILE`，不要在文档、截图或日志中记录实际值与个人文件路径。
- 默认使用 `MARKET_MODE=real` 验证双边链路；生成 README 截图时必须改为 `MARKET_MODE=demo`。

### 2.2 数据目录

- SQLite 默认位于 `data/rental.sqlite`，上传文件位于 `data/uploads/`。
- `data/` 必须保持在 Git 忽略范围内，目录权限应为 `0700`，数据库与迁移备份为 `0600`。
- 每次试点前使用新的隔离目录，或先确认旧数据已经按内部流程安全销毁。
- 升级已有数据库前保留程序自动生成的同目录迁移备份；试点结束后，只有负责人可以按保留策略删除数据库、WAL、SHM、备份与上传目录。

## 3. 自动发布闸门

在项目根目录按顺序运行：

```bash
npm ci
npm run check
npm test
npm run test:e2e
npm run eval:marketplace
npm run smoke:bilateral
git diff --check
git status --short
```

通过标准：

- Node 测试 166 项全部通过，跳过数为 0。
- Playwright 10 个场景全部通过，包括双账号真实链路，跳过数为 0。
- 市场评测的硬冲突误放行、私密字段泄露和 seed-to-case 均为 0。
- 双边 smoke 的 7 个布尔护栏全部为 `true`，`privateLeakCount` 与 `seedCandidateCount` 都为 0。
- `git diff --check` 无输出；`git status --short` 只包含本轮计划内文件。

任何一项失败都停止试点，不以人工“看起来能用”替代自动闸门。

## 4. 双账号人工验收

准备 Chrome 普通窗口和无痕窗口，或两个完全独立的浏览器资料目录。

1. 账号 A 设置虚构联系人，发布一条找房任务。
2. 确认真实市场没有供给时显示 0 个候选，不出现样板房。
3. 账号 B 设置另一条虚构联系人，用自然语言发布符合条件的个人房源。
4. 上传四类测试材料和一张测试房间图，由测试审核员在隔离环境标记通过。
5. 确认 A 与 B 得到同一个匹配案例，公开卡片不出现最高预算、最低授权价、精确地址和材料路径。
6. 由问题目标方回答全部阻断澄清，另一方只能看到待补充数量和类别。
7. 两端对比条款版本、哈希对应的公开内容与更新时间。
8. A 单方确认后，两端都不能读取联系人。
9. B 确认同版条款后，两端分别主动点击，且只能读取对方联系人。
10. 任一方提出看房时间，由另一方接受；刷新后约定状态仍存在。
11. 暂停房源任务，确认联系人立即重新锁定、未完成看房提议取消、案例要求重新确认。
12. 用第三个账号读取任务、案例、联系人和图片，确认分别得到 404 或无权限状态。

## 5. 浏览器与可访问性探索

人工记录测试时间、浏览器版本、设备尺寸、问题和证据，不在截图中保留任何真实敏感信息。

- macOS 当前稳定版 Chrome 与 Safari。
- 320、375、430 px；竖屏与横屏切换。
- 鼠标、触摸板、仅键盘和 VoiceOver 基础路径。
- Tab 顺序、焦点可见、弹层焦点限制、Esc 关闭与触发点焦点恢复。
- `prefers-reduced-motion` 开启时无非必要位移动画。
- 慢速网络、短暂离线、恢复和服务端 5xx；连接失败状态必须持续可见。
- 中文长文本、emoji、单双引号、尖括号和 HTML 片段只能作为文本显示。
- real/demo 标识、真实空结果和演示 fixture 不混淆。

## 6. 故障演练矩阵

| 故障 | 注入方法 | 用户可见状态 | 稳定代码或审计 | 安全恢复 |
|:---:|:---:|:---:|:---:|:---:|
| Qwen 超时 | 模型客户端使用超时或拒绝 Promise | 显示“确定性解析 · 安全模式”，表单仍可继续 | `AI_PROVIDER_ERROR`；不回显 provider body | 最多一次受控重试，随后规则降级 |
| Qwen 429 | 模拟 provider 429，或触发本地 AI 配额 | 请求不无限旋转；本地配额返回明确限流 | `AI_RATE_LIMITED` 或 HTTP 429 | 等待退避窗口；不得重复扣预算 |
| Qwen 坏 JSON | 首次返回非 JSON，第二次返回修复契约 | 用户不看到原始模型文本 | 格式修复调用最多一次 | 修复仍失败则规则降级 |
| Worker 中途退出 | 领取 outbox 后不完成，推进 fake clock 超过租约 | 任务保持“持续匹配中”，健康状态显示积压 | 过期租约回收；终态写 `worker.match_failed` | 新 worker 只领取同一幂等事件一次 |
| SQLite busy/locked | 另一连接持有 `BEGIN IMMEDIATE` 写锁 | 写操作失败时显示可重试错误，不伪造成功 | 内部 `SQLITE_BUSY`，对外不泄露路径或 SQL | `busy_timeout=5000`；释放锁后重放相同 `clientRequestId` |
| 创建响应丢失 | 服务端提交后丢弃客户端响应，再用相同 ID 重试 | 只出现一个任务 | `clientRequestId` 与 outbox dedupe key | 返回原任务并标记幂等 |
| 恶意图片 | JPEG MIME 携带文本/SVG、动画或像素炸弹 | 图片旁显示上传失败，任务信息不丢 | `MEDIA_DECODE_FAILED`、`MEDIA_MIME_MISMATCH`、`MEDIA_PIXEL_LIMIT` | 用户更换文件；失败内容不进入公开目录 |
| Cookie 过期或撤销 | 推进 fake clock，或调用会话撤销 | 回到未登录/新会话状态，不展示旧任务 | `SESSION_INVALID` | 重新建立会话；旧 Cookie 立即无效 |
| 条款确认并发冲突 | 两端用过期 hash/version 同时确认 | 旧端显示条款已变化 | HTTP 409 与稳定冲突码 | 刷新当前条款后由用户重新确认 |
| 联系人读取前暂停 | 第二方确认后、读取前暂停任一任务 | 查看按钮消失或返回锁定 | `CONTACT_LOCKED`、`contact.revoked` | 恢复任务、重算并由双方重新确认 |

自动证据分布在 `siliconflow-client.test.mjs`、`server-rate-limit.test.mjs`、`outbox-repository.test.mjs`、`database-migrations.test.mjs`、`server-api.test.mjs`、`server-media-api.test.mjs`、`session-service.test.mjs`、`confirmation-service.test.mjs`、`contact-grant-service.test.mjs` 和双边 smoke 中。人工演练只补浏览器、网络和操作系统层面的观察，不替代这些测试。

## 7. 观测与试点决策

每天运行：

```bash
npm run metrics:summary
```

只允许输出聚合计数与耗时，不输出联系人、精确地址、原话、预算上限、底价或材料 ID。重点关注：任务激活、候选形成、澄清完成、条款就绪、双方确认、联系人解锁、看房接受、举报和从创建到首候选的 P50/P95。

进入下一批试点必须同时满足：

- 安全事件为 0，私密泄露扫描为 0。
- 硬冲突误放行为 0，fixture 进入真实案例为 0。
- 所有联系人解锁都有双方同版确认记录。
- 任务暂停、关闭、过期和变更后的授权撤销成功率为 100%。
- 阻断级体验问题为 0；其余问题有负责人、复现步骤和修复版本。

## 8. 回滚与事故处理

1. 立即停止服务并暂停新增测试账号。
2. 保留只读事故副本和应用日志，限制访问人员；不要把数据库或上传目录发到聊天工具。
3. 若涉及联系人或材料越权，视为阻断级安全事故，撤销全部相关会话与授权。
4. 恢复到最近通过全部闸门的提交，使用隔离数据目录重新验证。
5. 完成根因、影响范围、修复和回归测试后，重新执行第 3 节全部命令。

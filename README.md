# 住哪儿 · AI 原生租房匹配

一个 iPhone-first 的交互原型，只允许房东本人直租与当前租客个人转租。产品不做房源社区：用户发布任务后，双方 AI 分身先完成结构化、核验、硬筛、协商和结果整理，本人从候选阶段开始介入。

## 当前可以体验

- 底部中间加号新建“我要找房”或“我要出租”任务，不再用全局大按钮切换身份。
- 用自然语言或语音描述找房需求，只补问真正缺失的条件。
- 通过地图界面选择商圈、地铁站、自定义地点和范围半径，并调用系统定位。
- 确认任务后进入持续匹配页，实际按阶段更新已查看数量、合适数量和事件流。
- 找房端从测试房源中完成风控、硬筛、议价与最多三套候选交付。
- 出租端真实反向匹配十位租客，覆盖性别、整租、区域、预算、租期、入住日和独卫冲突。
- 候选按接收方需求重组，不照搬发布者原文；可查看缺点、资料来源和结构化协商记录。
- 出租发布可调用系统相机或照片选择器，预览用户实际选择的图片。
- 数据页展示任务、匹配、合适与确认漏斗；生产版本将由不可变业务事件聚合。
- 举报先退出新匹配；客观收费或角色冲突证据命中后执行实名主体级处罚。

## 产品与系统架构

完整的信息架构、双边状态机、匹配流水线、数据库表、行级权限、地图与媒体方案见：

- [产品逻辑与系统架构](./docs/product-architecture.md)

生产版本需要账号、PostgreSQL、私有对象存储、任务队列、地理与路线服务、推送以及服务端匹配编排。用户数据不采用“每人一个数据库”，而是在同一数据库中以 `owner_id` 和行级安全策略强制隔离；精确地址、身份材料和私密价格授权单独保护。

## 当前真实程度

- 自由输入会真实改变区域、预算、入住时间、通勤、合租和设施条件。
- 硬条件、角色限制、禁止费用与私密价格边界由确定性规则执行，生成式结果不能绕过。
- 找房端有 10 位租客 × 10 套房源评测集；出租端新增 10 位租客对单套房源的对称评测。
- 动态匹配页展示真实计算结果的分阶段释放，不再在确认后瞬间写死“找到 3 套”。
- 房源、账号和交易仍是模拟数据；地图底图为交互原型，原生版应接入 MapKit 与路线矩阵。
- 尚未接入真实账号、数据库、实名服务、推送、合同或支付，请勿录入真实证件和隐私材料。

## 本地运行

```bash
npm start
```

打开 <http://127.0.0.1:4173>。

## 自动检查

```bash
npm test
npm run check
```

测试覆盖需求解析、供需双向匹配、风控、禁止费用、议价隐私、举报与候选选择。

## AI 链路评测

密钥只从本地文件读取，不会写入仓库、报告或前端。评测覆盖需求结构化、供给结构化、风控、匹配、议价与最终交付；模型输出之后仍需经过确定性策略闸门。

```bash
npm run eval:ai -- --key-file "/absolute/path/to/provider-key.txt"
```

结果写入：

- `evals/results/latest-summary.md`：可提交的结论报告；
- `evals/results/latest.json`：本机详细结果，已被 Git 忽略。

## 主要代码

- `src/app.mjs`：信息架构、任务状态与交互；
- `src/app.css`：iOS-first 视觉系统、动态匹配与地图界面；
- `src/demand-parser.mjs`：自然语言需求解析与缺口识别；
- `src/simulation-engine.mjs`：双向匹配、议价、风控、举报和发布规则；
- `src/fixtures.mjs`：房源、找房委托与边界场景；
- `src/ai/`：真实 AI 环节的结构化契约与策略闸门；
- `evals/`：端到端评测数据与运行器；
- `tests/`：业务规则自动回归。
